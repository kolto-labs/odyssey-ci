## CI design

Everything runs from one workflow, `.github/workflows/ci.yml`; see [ci.md](ci.md).

- **Triggers:** push to `main`, pull requests (same-repository only; fork and
  Dependabot pull requests skip every job that needs secrets), published releases,
  a Monday and Thursday schedule (`23 4 * * 1,4`) and `workflow_dispatch`. A newer
  push to a pull request cancels its older run; the other events share one
  concurrency group, so two full runs never overlap and none is cancelled while running.
- **`game` (k1, k2; one at a time):** look up the encrypted game cache, or
  download with SteamCMD (saved login if `STEAM_CONFIG_VDF` is set, then password,
  then `STEAM_RECOVERY_CODE`, then `STEAM_GUARD_CODES`; stops at Steam's rate limit) and save it. Fails only if the game is still missing.
  `.bik` movies are never cached. See [steam.md](steam.md).
- **`mods`:** restores the Actions cache, optionally refreshes the Cloudflare R2
  bucket (write credentials; skipped without them), then runs `cache.py refresh`,
  which revalidates each archive and keeps at most 3 GiB (pinned first, then
  smallest) in the Actions cache. Unresolved links are reported, not errors, and
  the job never blocks an install. It is the only job that saves the cache. See
  [cache.md](cache.md).
- **`install` (k1, k2 × rust, typescript × cli, gui):** restore and verify the game
  (a cache miss fails the lane), restore archives, then run `ports.py`. Per
  archive, restore takes the first of: the restored Actions-cache copy
  (revalidated by conditional GET), the optional R2 bucket (read-only credentials),
  P2P (inert: no pin has a magnet), the website. The last valid local copy is used
  if the website is unreachable. The lane stops before install only when no source
  yields a required archive. TypeScript lanes fail at the start if
  `ci/<game>-typescript-review.json` is missing. Lanes run per game even if the
  other game failed. See [ports.md](ports.md).
- **`manual` (k1, k2):** same restores, then `manual.py` with a reviewed plan. The
  job fails if `ci/<game>-manual-plan.json` is missing. See
  [manual-lane.md](manual-lane.md).
- **`p2p-loopback`:** builds ModSync.rs and runs a loopback seed-to-download
  transfer. See below for what that does and does not prove.

All jobs use Linux runners because the adapters are POSIX and Xvfb only.

## What each implementation does today

- **ModSync.rs:** has peer-to-peer transfer through `librqbit`
  (`torrent-seed`, `torrent-download`). The `p2p-loopback` job proves one thing:
  a seed and a downloader on the same runner move a random 3 MB zip byte for byte
  over the peer connection (the seeder must report uploading the whole file), and a
  download with a wrong `--sha256` is refused by the hash check after the transfer,
  with no output file. It does
  not test DHT, trackers, SOCKS5, NAT traversal or any GUI.
- **ModSync.ts:** has no P2P. The CI lanes build it from `feat/physical-install`
  (`MODSYNC_TS_REF`) and the `cli` lane passes `--ci-physical-install`; the default
  branch throws for every non-dry-run install. The TypeScript lanes now have committed
  delegated review manifests, apply the same reviewed policy skips as Rust (`--select`
  of the remaining components; the Rust-only unreviewed-draft pins are not applied) and
  install Wine for `Execute` and legacy patchers. Not yet confirmed by a CI run. The
  GUI/server route still reports `physicalRestore: false`, so the TypeScript `gui` lane
  is the least likely to complete.

## Rust lane gaps

- 69 K1 components had no `Instructions` when last measured. `ports.py` deselects
  each of them and its dependents as an error, installs the rest of the guide, and then
  fails the Rust lane (status `incomplete`).
- Generated draft instructions need a human review with notes. `gui_rust.py`
  cannot authorize one and stops (a deselected draft component is not installed and
  does not stop it).
- The committed `unreviewed_draft` lane skips (k1 150, k2 118 plus the dependent
  `Extended Korriban Arrival`; owner decision 2026-10-18) are removed: they made the k2
  Rust CLI lane of CI run 39425722697 install a fraction of the guide and fail. The Rust
  lanes now accept every generated draft with clean diagnostics (`convert --review-draft`)
  and let `validate`/`install` check it; a draft that cannot be accepted is deselected as
  an error with its dependents and fails the lane after the rest is installed. Only an
  archive no source can provide (or the reviewed uncached-by-policy steps) is a warning,
  and a lane missing only those passes as `partial`. Unit-tested with fake tool output
  only; not yet run against the CI-built Rust binary; see
  [ports.md](ports.md#generated-draft-acceptance).
- Rust `validate` failures that name a component (`Error: <Component> / step N (...)`, as
  `Ebon Hawk Downloadable Map` did in k2 CLI/GUI run 39141977764) are quarantined at run
  time: the component and its dependents are deselected and `validate` re-runs, at most 15
  times and never more than 15% of the selected components. Every quarantined component is
  in the lane report (`quarantined_validate_failures`) and an `::error::` line, and the
  lane fails (`incomplete`) once the rest is installed. Errors that name no component, caps, a missing game
  and install-time failures (K1 `Helena Shan Improvement`, which needs a restored game
  before a retry) still fail the lane; failures now print a bounded evidence excerpt and
  record the failing component as `failure`. Unit-tested with fake tool output only; not yet
  run in CI. See [ports.md](ports.md#runtime-quarantine-of-validate-failures-rust-lanes-only).
- Archive file names containing `[ ] * ? { }` were reported to abort
  `--auto-generate-local`. That behavior is in ModSync.rs; it was not re-checked
  for this update.
- Widescreen sections are not covered by either GUI driver: `gui_rust.py` excludes
  widescreen-only components (listed as not covered) and `gui_typescript.py` refuses
  a selection with widescreen mods.
